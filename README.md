# Майстерня на Фонтані

Сайт семейной мастерской в Одессе: ремонт одежды и обуви, пошив, изготовление ключей и заточка. Новый дизайн — светлый фон, терракотовые акценты, фотографии и одна основная страница на украинском языке.

**Сайт:** https://masterskaya-na-fontane.od.ua/ua

Личного кабинета, CRM и базы заказов в этой версии нет. Форма отправляет обращение в Telegram после подключения бота; прежняя почта Resend остаётся запасным каналом. Пока Telegram не настроен, работает прежняя отправка на почту. Воскресенье: **12:00–17:00**.

### Пример: поменять воскресные часы

Открой `src/content/site.ts`, найди объект с `label: "Неділя"` и поменяй:

```ts
opens: "12:00",
closes: "17:00",
```

Часы в контактах и разметке Google обновятся вместе: второй копии расписания нет.

### Пример: поменять фотографию

1. Положи файл в `public/images`, например `new-workshop.jpg`.
2. В `src/content/home.ts` или `src/content/services.ts` укажи `/images/new-workshop.jpg`.
3. Обнови `imageAlt`: это описание для людей, использующих экранный диктор, и поисковых систем.

Не добавляй `public` в адрес картинки. `next/image` автоматически создаёт уменьшенные версии. Архивное фото и остальные изображения сохранены из предыдущего сайта.

## Структура проекта

- `src/app` — страницы, корневой layout, SEO-файлы и API.
- `src/content` — редактируемая информация и украинские тексты.
- `src/components/sections` — отдельный компонент для каждого раздела.
- `src/components/layout` — общие шапка, подвал и логотип.
- `src/components/contact` — интерактивная форма и выбор услуги.
- `src/components/ui` — небольшой общий набор иконок.
- `src/lib/contact` — проверка формы, ограничения и доставка: `delivery.ts` выбирает канал, `telegram.ts` отправляет в Telegram, `email.ts` — через Resend.
- `src/lib/seo.ts` — метаданные и JSON-LD из общих данных.
- `src/styles` — оформление сайта, включая адаптивные правила.
- `config` — старые URL и их назначения.
- `tests` — проверки формы, ошибок доставки, расписания и перенаправлений.
- `scripts/smoke.mjs` — проверка собранного сайта по HTTP; все ключи доставки отключены.

Порядок главной виден прямо в `src/app/ua/page.tsx`: `Hero → Services → Story → RequestSection → Faq → Contact`. Большинство разделов — серверные компоненты. JavaScript на клиенте нужен только форме и кнопкам, которые подставляют услугу в сообщение.

## Запуск на компьютере

Нужен **Node.js 22 или 24**. Рекомендуемая версия указана в `.nvmrc`.

```bash
npm ci
npm run dev
```

Открой http://localhost:3000/ua. Главная и карта работают без почтового ключа. Для формы скопируй `.env.example` в `.env.local` и заполни Telegram-переменные или `RESEND_API_KEY`.

```bash
cp .env.example .env.local
```

## Заявки в Telegram и запасная почта

Маршрут `POST /api/contact` проверяет данные на сервере. При подключённом боте сначала отправляет заявку в Telegram. Если Telegram не принял её, пробует Resend. При успехе Telegram отдельного письма не будет. Если настройки Telegram ещё не добавлены, продолжает работать прежняя почта.

| Переменная                 | Назначение                                                                  |
| -------------------------- | --------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`       | Токен нового бота от BotFather; только на сервере                           |
| `TELEGRAM_CHAT_ID`         | Числовой ID личного чата или закрытой группы; у группы обычно отрицательный |
| `RESEND_API_KEY`           | Прежний ключ Resend: запасной канал при проблемах Telegram                  |
| `CONTACT_EMAIL_TO`         | Необязательно: адрес получателя вместо прежнего                             |
| `CONTACT_EMAIL_FROM`       | Необязательно: отправитель, разрешённый в Resend                            |
| `GOOGLE_SITE_VERIFICATION` | Необязательно: токен подтверждения сайта в Google Search Console            |

### Подключение бота, один раз

1. Открой официальный [@BotFather](https://t.me/BotFather), отправь `/newbot`, задай имя и свободный username с окончанием `bot`. Для сайта лучше отдельный бот.
2. Сохрани полученный токен в `TELEGRAM_BOT_TOKEN` в `.env.local` на своём компьютере. **Не добавляй токен в GitHub, переписку или переменные с `NEXT_PUBLIC_`.**
3. Открой созданного бота в Telegram и нажми **Start**. Для совместной работы можно создать закрытую группу с мамой и собой, добавить бота и отправить в группе `/start@имя_бота`. Права администратора для обычной отправки в группу не нужны, но бот должен иметь право писать сообщения.
4. В папке проекта выполни:

   ```bash
   node --env-file=.env.local scripts/telegram-chat-id.mjs
   ```

   Команда покажет ID и названия доступных чатов, не печатая токен. Выбери нужный чат и добавь его ID в `TELEGRAM_CHAT_ID` в `.env.local`. Если пусто — снова напиши `/start` боту и повтори. Скрипт рассчитан на отдельного нового бота: существующему боту с webhook он настройки не меняет.

5. На Vercel открой проект **masterskay → Settings → Environment Variables**. Добавь `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` для **Production**. Существующий `RESEND_API_KEY` оставь для резерва. Для Preview либо не задавай реальные ключи, либо используй отдельный тестовый чат.
6. Выполни **Redeploy** последнего production-развёртывания, чтобы применить переменные. Для разработки перезапусти `npm run dev`.
7. Отправь одну заявку со своим номером на сайте и проверь сообщение в нужном чате. В нём будут имя, телефон, описание и номер запроса. Отвечать клиенту нужно по указанному телефону: это уведомление для мастерской, клиентский Telegram сайт не запрашивает.

Отдельный сервер бота, Railway, постоянный polling или webhook не нужны: сайт вызывает `sendMessage` при получении формы. `getUpdates` используется только при первоначальном определении ID.

### Доставка и ошибки

Успех показывается **только после подтверждения Telegram с `message_id` либо Resend с идентификатором письма**. Это не подтверждение прочтения. Если оба доступных канала отказали, форма сохраняет введённый текст и предлагает повторить запрос или позвонить. Если Telegram отказал, в серверном логе будет безопасное сообщение `Contact Telegram delivery failed`; тела заявок, токены и URL Telegram туда не выводятся.

Тестовый отправитель `onboarding@resend.dev` сохранён для совместимости. Resend ограничивает круг получателей для такого отправителя. Для отправки на произвольную почту подтверди домен в Resend и укажи разрешённый `CONTACT_EMAIL_FROM`.

Повторный клик блокируется в браузере, Resend получает ключ повторной отправки. Для Telegram повторные запросы с одинаковым содержимым и номером объединяются в памяти одного экземпляра на 10 минут (не более 500 записей). Это **не гарантия единственной доставки** между разными экземплярами или перезапусками: у Telegram `sendMessage` нет нашего устойчивого ключа идемпотентности. При таймауте Telegram мог успеть принять сообщение, а сайт — отправить запасное письмо; номер запроса поможет узнать дубль. Базы заявок, фоновой очереди и автоматического повторения после отказа в этой версии нет.

Проверка номера, ограничение размера запроса и скрытое антиспам-поле включены. Ограничитель частоты — 5 запросов за 10 минут на IP (при отсутствии IP — на номер), в памяти одного серверного экземпляра. При росте нагрузки/спаме понадобится общий Redis/Turnstile или ограничение на хостинге.

Тесты подставляют ответы обоих сервисов, HTTP-проверки отключают все ключи: **настоящие сообщения не отправляются**.

## Украинский язык, старые ссылки и Google

- Основной адрес остаётся `/ua`; язык документа — `uk`, как требует стандарт HTML.
- `/`, `/ru` и `/en` перенаправляются на `/ua`.
- Старые страницы услуг и контактов перенаправляются кодом **308** на соответствующий раздел главной. Неизвестные адреса возвращают 404.
- `next-intl`, переключатель языка и дубли переводов удалены.
- `title`, описание, canonical, Open Graph и Twitter Card находятся в `src/lib/seo.ts`, их тексты — в `src/content/site.ts`.
- JSON-LD LocalBusiness использует реальные адрес, услуги и общее расписание. Вымышленных отзывов, оценок и цен нет.
- `/sitemap.xml` содержит только каноническую страницу. `/robots.txt` разрешает индексирование сайта и закрывает API от обхода.
- В `head` нет бесполезного `meta keywords`.
- Шрифты берутся из npm-пакетов Fontsource и отдаются с сайта: браузер не загружает их с Google Fonts.
- Карта Google подгружается лениво. Кнопка маршрута работает отдельно от встроенной карты.

После публикации проверь `/ua` через «Проверка URL» в Search Console и отправь `https://masterskaya-na-fontane.od.ua/sitemap.xml`. Объединение страниц меняет структуру индексирования; позиции не гарантируются одними метатегами. Для отдельных направлений позже можно вернуть подробные украинские страницы, если данные Search Console покажут такую необходимость.

## Публикация и откат

Если хостинг подключён к `main`, он начнёт сборку после обновления ветки. Сохрани на хостинге `RESEND_API_KEY` и при необходимости добавь остальные переменные из примера. Команда сборки — `npm run build`, запуска — `npm start`; отдельный сервер Express не нужен. Статический `output: "export"` использовать нельзя: форма требует серверный маршрут.

Перед ребрендингом сохранена ветка `backup/before-uk-rebrand-2026-09-20`. Для отката рабочего `main` используй `git revert <SHA-коммита-ребрендинга>` и отправь новый коммит — переписывать историю через force push не требуется.

## Продвижение и будущий короткий домен

1. Подтверди доступ к существующей карточке мастерской в Google Business Profile. Сверь реальное название, категорию, адрес, телефоны, сайт и расписание (воскресенье с 12:00). Добавь фото входа и работ, список услуг. Не создавай дубль карточки ради нового дизайна.
2. Попроси реальных клиентов оставлять честные отзывы; отвечай на них. Удобно сделать QR-ссылку на отзыв на стойке. Не покупай отзывы и не предлагай скидку за положительную оценку.
3. В Google Search Console подтверди сайт, отправь `/sitemap.xml`, проверь индексирование `/ua`. Смотри, по каким запросам показывается мастерская и какие приводят клики.
4. Добавляй полезные примеры работ до/после, реальные условия и ориентиры цен после согласования с мастерами. Если нужны отдельные поисковые направления, стоит сделать две содержательные украинские страницы: ремонт одежды и ремонт обуви в Одессе, с примерами и ответами на вопросы. Меню при этом может остаться простым. Не создавай десятки одинаковых страниц под районы.
5. Оценивай результат по звонкам, заявкам и действиям в карточке, а не только позиции одного запроса. Технические SEO-настройки уже есть, но не гарантируют первое место.

Идеи доменов для обсуждения: `nafontani.com.ua`, `fontan63.com.ua`, `nafontani.od.ua`. **Доступность и стоимость не проверены; ничего не зарегистрировано.** Основной URL сейчас не меняется.

Если выбран новый домен: сначала зарегистрировать и подключить его с HTTPS; затем обновить `site.url` в `src/content/site.ts`, настроить постоянные 301/308 перенаправления со всех старых URL на соответствующие новые, обновить проверки домена в `tests`/`scripts`, canonical, sitemap и ссылку в карточке Google. В Search Console подтвердить оба домена и подать смену адреса. Старый домен и перенаправления сохранять минимум год, по возможности дольше. Не запускать два индексируемых дубликата сайта. При переезде возможны временные колебания позиций; короткое имя само по себе не повышает позиции.

Источники: [местное продвижение Google](https://support.google.com/business/answer/7091), [основы SEO](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [переезд на другой домен](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes), [Telegram Bot API](https://core.telegram.org/bots/api).

## Лёгкие анимации

- `src/styles/motion.css` — реакции кнопок, стрелок, фото и раскрытие FAQ. Меняй длительности и величину `scale` здесь.
- `src/components/motion/scroll-reveal.tsx` — однократное появление отмеченных блоков при прокрутке: 560 мс, смещение 14 px. Без дополнительных библиотек и обработчиков каждого движения скролла.
- `data-reveal` на блоке включает появление, `data-reveal-delay` задаёт задержку до 140 мс. Убери атрибут, чтобы исключить конкретный блок.
- Контент сразу виден в HTML, в том числе без JavaScript. Форма и карта не анимируются. При фокусе с клавиатуры движение соответствующего блока отменяется.
- `prefers-reduced-motion` отключает анимации, включая смену настройки во время просмотра. На iOS это системная настройка «Уменьшение движения». Эффекты наведения включаются только для мыши/трекпада.
